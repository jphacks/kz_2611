## 1. コンセプト
フッ軽遊び

## 2. 対象ユーザー
- 大学生・若者
- 遊びたいけど積極性はない
- 想定する遊び: カラオケ / ドライブ / バドミントン / ご飯 / なんとなく集まりたい

## 3. 課題
| # | 課題 | 背景（マップの記載） |
|---|------|------|
| P1 | ちょっと遊びたい時に LINE だと誘いづらい | DM・グループで個別に誘いにくい |
| P2 | 誘ってから返信が来るまでのラグがだるい | 連絡に気付かない／気付いても返信しない（様子をうかがう、即レスしたくない、一番手で断りたくない） |
| P3 | 断る・集まらないのが気まずい | 断りづらい、集まらないと悲しい |
| P4 | メンツが分からないと行きにくい | 皆メンツを確認している／温度感が違うと行きにくい／普通にだるいが人が集まるなら行く |
| P5 | 友達の友達が呼ばれるのがだるい | 知らない人・嫌いな人がいる可能性 |
| P6 | 何をしたいか決めないといけない | — |
| P7 | 会ってから決めたい | — |

## 4. 解決方針（マップの記載）
- DM やグループで個別に誘わない → 募集・応募の形式にする
- 誘ってから時間制限を設ける
- 誰が参加するか分かるようにする
- グループを作成でき、グループ内で募集をかけられる
- グループチャット自体は要らない

## 5. 機能
| # | 機能 | 内容 | 不明な点 |
|---|------|------|------|
| F1 | グループ | グループを作成できる。作成時に友達を選択し、グループ名・プロフィールを入力する（UI設計図） | 参加・招待の方法、人数上限、グループの「プロフィール」の中身、募集との関係（下記「矛盾・要確認」） |
| F2 | 募集作成 | 「誘う」ボタンから、場所・時間・人数・表示時間を設定して公開する（UI設計図） | 「会ってから決める」の扱い、公開する相手の選び方 |
| F3 | 応募 | 掲示板でイベントに参加し、取り消せる。元資料は主催者アイコンの右スワイプ | 実装では左の自分の指を右へスライドして主催者の指先にタッチする。travel = カード幅 × 0.25、その半分を**超えて**離すと参加。参加済みは左へ戻して取り消し。主催は左スワイプで掲示取り消しの確認。参加後にチャットは自動で開かず、成功時に参加演出を表示（#97 #94 #102） |
| F4 | 時間制限 | 募集に時間制限を設ける。募集作成時に「表示時間」を設定する（UI設計図）。カードの外枠が残り時間のインジケーターになる（音声） | 解決済み（#27 #42 #44 #59 #60）: 表示時間が過ぎた募集は掲示板から消え、トークには終了として残り、チャットは読める。定員到達時は参加成功と同じ処理で即終了（#44）。時・分のホイール（分は5分刻み）で選び、保存時に `HH:MM〜`（選んだ時・分が保存時点より前なら `明日 HH:MM〜`）へ変換（#83）。ゲージは時計回りに減少、通常は黒、残り 10 分以下は黄（#27 #59 #60） |
| F5 | 参加者の表示 | 誰が参加するか分かる。カードに参加者のアイコンが並び、主催者アイコンの縁が何人集まっているかのインジケーターになる。参加者のアイコンをタップすると、誰が参加しているかの詳細が見える（音声） | 解決済み（#33 #44 #53）: カードに参加人数（count / capacity、下限がある場合は count / min〜max）と参加者アバター（最大 3 人）を表示。主催者アイコンの縁の白リングで参加人数を示す。満員の募集は参加していない人には掲示板に表示しない（#33、定員到達で自動終了 #44）。インジケーターの色は背景と区別（#53） |
| F6 | イベントの編集・削除 | 作成者だけがイベントを編集・削除できる（UI設計図） | 解決済み（#45 #51 #97）: 主催は指の帯を左スワイプで掲示取り消し（確認ダイアログあり）。編集項目は title / place / time_text / capacity / capacity_min / duration_min / group_id（API 契約どおり）。duration_min を変えると expires_at = created_at + 新しい分数 |
| F7 | イベント内のトーク | 参加したイベントの中だけのトーク。今まで参加したイベントと今参加しているイベントのトークを一覧で表示し、トーク画面へ進む（UI設計図）。掲示板でイベントのカードをタップすると、そのイベントのチャットがポップアップし、普通のチャット欄のように使える（音声） | 解決済み（#44 #54）: 参加していない人がカードをタップしてもチャットは読めず「参加する」ボタンだけを表示。参加を取り消すとトーク一覧から消え、チャットも読めなくなる（参加者と主催者だけが読める）。参加・退出・定員到達時にシステムメッセージを流す（#44）。参加してもチャットは自動で開かない（#54） |
| F8 | 友達（フォロー） | 友達の一覧を表示し、友達を削除できる。QRや招待リンクで友達を追加する（UI設計図） | 「フォロー」と「友達」の違い（片方向か相互か）、承認の有無 |
| F9 | プロフィール | 自身のプロフィール（アイコン・名前）（UI設計図） | 編集の可否、他の人から見える範囲 |

作らないもの:
- グループチャット
- 暇かどうかが分かる機能
- 「行けたら行く」機能

### 矛盾・要確認
- 募集の公開範囲: アイデアマップは「グループ内で募集をかける」、UI設計図は掲示板を「(全体)」と書き、グループ作成は「フォロー欄」の下にある。募集をグループに出すのか、友達全体に出すのか不明
- トーク: アイデアマップは「グループチャット自体は要らない」、UI設計図には「参加したイベント内限定のトーク」があり、音声でもカードからイベントのチャットを開く。イベント内のトークはグループチャットとは別物として作るのか要確認

## 6. 画面（UI設計図より）
アプリ起動後、次の5つに分かれる。「（下）」は図の記載どおり（画面下部のタブを指すと思われるが不明）。

1. 掲示板（ホーム）(全体)
   - 人数・場所・時間・表示時間などを表示
   - イベントを選択 → 参加 → 参加の取り消し
   - 作成者のみ、イベントの編集・削除
   - 詳細は 6.1、6.2（手書きUI図と音声）
2. 誘うボタン（下）
   - 場所・時間・人数・表示時間を設定 → 公開
3. 参加したイベント内限定のトーク（下）
   - 今まで参加したイベントと今参加しているイベントのトークを表示 → トーク画面へ
4. フォロー欄（下）
   - 友達の一覧を表示 → 友達の削除
   - グループ作成 → 友達を選択、グループ名・プロフィールを入力
   - QRや招待リンクで友達追加
5. プロフィール（下）
   - 自身のプロフィール → アイコン・名前

実装では起動時に保存トークンを確認し、未ログインかつ案内未完了の端末はオンボーディング後にログイン・登録へ進む。ログイン後は下タブ（掲示板・トーク・誘う・フォロー・プロフィール）で切り替える（#99、Main.tsx）。

### 6.1 掲示板のイベントカード（手書きUI図・音声）
元資料のイメージ: [掲示板](design/ui-image/01_home.png)。実装では黒地・角丸27、縦横比660:580の指先タッチカードが並ぶ（#97）。

| 位置 | 表示するもの |
|---|---|
| カードの外枠 | 残り時間ゲージ（黒、残り 10 分以下は黄、時計回りに減少）（#27 #59 #60） |
| カード内の大きな丸 | 主催者（誘っている人）のアイコン（左側）（#22 #25） |
| 主催者アイコンの縁 | 人数リング（白、時計回りに count / capacity）（#27 #53） |
| 主催者アイコンの下 | 主催者の名前 |
| アイコンの横・中央 | 誘うときのタイトル（例: カラオケ）、その下に時間（例: 19:00〜） |
| タイトルの下 | 現在参加している他の人のアイコン |
| 右側 | 参加人数／定員（count / capacity、下限がある場合は count / min〜max）と残り時間（あと◯分）（#22 #25 #27） |

- 大きな丸の位置: 実装は左側（#22 #25）
- 表示順: 主催の募集が先頭、その他は締切が近い順（#50 #55）

### 6.2 カードの操作（音声）
| 操作 | 結果 | イメージ |
|---|---|---|
| カードをタップ | そのイベントのチャットがポップアップする。上半分の詳細な情報は消え、タイトルだけが上に小さく表示され、その左に参加者のアイコンが並ぶ。普通のチャット欄のように使える | [元資料のイメージ](design/ui-image/02_event_chat.png) |
| チャットの入力欄をタップ | 端末のキーボードが下半分に出て、チャット欄はその上に表示される | [元資料のイメージ](design/ui-image/03_chat_keyboard.png) |
| 左の自分の指を右へスライド | 指先タッチで参加（#97）。成功時に約3秒の参加演出（#94 #102） | — |
| 参加済みカードの自分の指を左へ戻す | 参加を取り消す（#97） | — |
| 主催カードの指の帯を左にスワイプ | 掲示取り消しの確認をカード内に表示。主催の指は動かさない（#97） | — |
| 参加者のアイコンをタップ | 誰が参加しているかの詳細が見える | [元資料のイメージ](design/ui-image/04_participants.png) |

- 音声では「四角い縁をタップ」と言っている。実装はカード全体のタップ（#54）
- ポップアップの閉じ方: ×ボタンまたはシートを下にスワイプ。スワイプとタップの区別: 移動距離 8px 未満をタップとして扱う（#22）
- 参加の取り消し: 自分の指を左へ戻す、またはチャットメニューの「参加をやめる」（#46 #52 #97）
- 主催の掲示取り消し: 指の帯を左スワイプしてカード内で確認後に削除（#97）
- 参加してもチャットは自動で開かない（#54）。旧アイコンの自動的な揺れは現実装にない。指をドラッグすると進行ゲージと「近づいてる…」「もうすぐ…！」が変化する（#97）。状態・処理中・失敗時の詳細は [カードの状態](mock-decisions.md#カードの状態) を参照。

### 6.3 参加成立の演出（実装 #94 #102）
- 掲示板からの参加 API 成功時に、全画面で「とまった!!」・鳥・紙吹雪・ズーム等を表示する。失敗・取り消し・主催カードの表示では出さない。定員到達だけに限定しない。
- 約3秒（2800ms）で閉じ、タップで早く閉じられる。現在はヒットストップなし。Web は Canvas 1枚と CSS transform、Native は Animated。
- 効果音・振動はプロフィールで端末ごとに設定し、初期値は両方オン。非対応環境では鳴動しなくても演出を続ける。
- OS／ブラウザの「視差効果を減らす」が有効なら揺れ・フラッシュ・色収差を止める。ズーム・鳥など全アニメーションを停止する設定ではない。

### 6.4 初回案内（実装 #99）
- 未ログインかつ端末に完了記録がない場合に5ページ（コンセプト・誘う・友達の掲示板・指先タッチ・人数成立とチャット）を表示。ログイン中や完了済み端末には自動表示しない。
- 横スワイプ・ページの点・「次へ」で移動。「スキップ」「はじめる」で端末に完了を保存して認証へ進む。保存失敗はエラーを出して再試行できる。初期の保存領域読み込み失敗では認証を妨げない。
- ログイン画面から再表示できる。4枚目の指先タッチと5枚目の初回表示で本番と同じ演出を体験できる。自動デモは最初のタップ・スワイプ前に音を出さない。動きを減らす設定に対応する。

### 6.5 通知（Web Push、実装 #88）
- プロフィールの「通知を受け取る」で端末ごとに購読・解除する。通知の許可要求はボタン操作時のみ。対応 Web ブラウザの安全なコンテキストが必要で、iPhone／iPad はホーム画面に追加して開くよう案内する（実装の案内は iOS 16.4 以降）。
- 新しい募集は閲覧できる人へ、参加は主催者へ、満員終了は主催者と参加者へ送る。操作した本人には送らず、満員時に主催者へ参加通知を重ねて送らない。チャット新着や期限切れの通知は実装していない。
- 通知タップで `/?event=<id>` を開き、ログイン後に掲示板の該当チャットを開く。閲覧権限は通常どおり適用する。オフ・ログアウトではこの端末だけを解除する。
- API・購読の上限は [API 契約](api.md) の「通知・Web Push」を参照。

## 11. 開発の進め方

### 11.1 プロダクト・UI
- 画面を作る前に、コンセプトを1文、代表的な場面を3つ、中心にする「もの」を2つまで決める（内容は不明・要決定）
- 機能の一覧をそのまま画面やタブにしない
- デザインの現行ルールは [AGENTS.md](../AGENTS.md) 3章と app/src/ui/theme.ts。掲示板カードは X6 の指先タッチ（#97）を採用し、元資料の [Color Pop 見本](design/style11-colorpop.png) と区別する。
- F2 の入力項目は最小限にする（項目は不明・要決定）
- 機能を足すときは、先に仕様書を更新する。F1〜F9 に加え、参加演出・初回案内・Web Push は6章に記載した実装済み機能（#94 #102 #99 #88）。
- チーム外の人に使ってもらって確かめる（方法は不明）

### 11.2 リポジトリ・GitHub 運用
- リポジトリを公開にするか GitHub Pro にして main を保護し、CI が通らないとマージできないようにする（公開範囲は不明・要決定）
- ワークフロー・DB 変更・認証の変更だけ、他の1人が見る
- マージは squash に統一し、マージ後にブランチを自動で削除する
- Issue テンプレートで「何を・なぜ・完了条件」の3行を必須にする。着手したら「作業中」とコメントし、自分を担当者にする。ラベルは3つ
- 進捗は Issue と PR だけで管理し、手で書く進捗まとめは作らない（現行ルール: AGENTS.md）。
- README は提出物なので作品紹介とデモ URL だけにする。開発情報は CONTRIBUTING.md、ルールは AGENTS.md に書く
- AGENTS.md とファイル構成（機能ごとのファイル）は、メンバーが作業を始める前に用意する

### 11.3 デプロイ（Cloudflare）
- 現在の CI では main へのマージ後に本番 D1 の更新と Cloudflare Pages 公開を自動実行する。手動デプロイはしない（.github/workflows/ci.yml、AGENTS.md 9章）。staging 経由の旧案とは異なる。
- DB の変更は追加だけにし、古いアプリでも動くようにする。CI で DROP/RENAME と既存マイグレーションの変更を検出する
- 公開後に DB の接続とバージョンを確かめる（/api/health など）
- Cloudflare のトークンは権限を絞り、本番用の Environment secret に置く
- 審査前に本番を凍結する（時刻は不明・要決定）

### 11.4 実装・デモ
- 定員を設ける場合は、定員の確認と参加を1回の処理でまとめて行う（実装済み。定員到達で自動終了、#44）
- 定期的にデータを取得する場合は、画面が見えていないときは止め、失敗したら間隔を空ける（Cloudflare の無料枠は1日10万リクエスト）
- セッションに有効期限を付け、ログインと登録に試行回数の制限を入れる
- スマホ実機での通しデモと、予備のデモ動画を用意する
- 中間の締切を置く（スケジュールは不明・要決定）
