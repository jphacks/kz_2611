## 1. コンセプト
フッ軽遊び

## 2. 対象ユーザー
- 大学生・若者
- 遊びたいけど積極性はない
- 想定する遊び: カラオケ / ドライブ / バドミントン / ご飯 / なんとなく集まりたい

## 3. 課題
| # | 課題 | 背景（マップの記載） |
|---|------|------|
| P1 | ちょっと遊びたい時に LINE だと誘いづらい | DM・グループで個別に誘いにくい |
| P2 | 誘ってから返信が来るまでのラグがだるい | 連絡に気付かない／気付いても返信しない（様子をうかがう、即レスしたくない、一番手で断りたくない） |
| P3 | 断る・集まらないのが気まずい | 断りづらい、集まらないと悲しい |
| P4 | メンツが分からないと行きにくい | 皆メンツを確認している／温度感が違うと行きにくい／普通にだるいが人が集まるなら行く |
| P5 | 友達の友達が呼ばれるのがだるい | 知らない人・嫌いな人がいる可能性 |
| P6 | 何をしたいか決めないといけない | — |
| P7 | 会ってから決めたい | — |

## 4. 解決方針（マップの記載）
- DM やグループで個別に誘わない → 募集・応募の形式にする
- 誘ってから時間制限を設ける
- 誰が参加するか分かるようにする
- グループを作成でき、グループ内で募集をかけられる
- グループチャット自体は要らない

## 5. 機能
| # | 機能 | 内容 | 不明な点 |
|---|------|------|------|
| F1 | グループ | グループを作成できる。作成時に友達を選択し、グループ名・プロフィールを入力する（UI設計図） | 参加・招待の方法、人数上限、グループの「プロフィール」の中身、募集との関係（下記「矛盾・要確認」） |
| F2 | 募集作成 | 「誘う」ボタンから、場所・時間・人数・表示時間を設定して公開する（UI設計図） | 「会ってから決める」の扱い、公開する相手の選び方 |
| F3 | 応募 | 掲示板でイベントを選択して参加する。参加は取り消せる（UI設計図）。イベントのカードで、主催者のアイコンを指で押さえて右にスワイプすると参加できる（音声） | 参加を取り消す操作の方法、断る操作の有無 |
| F4 | 時間制限 | 募集に時間制限を設ける。募集作成時に「表示時間」を設定する（UI設計図）。カードの外枠が残り時間のインジケーターになる（音声） | 表示時間が過ぎたあとの扱い |
| F5 | 参加者の表示 | 誰が参加するか分かる。カードに参加者のアイコンが並び、主催者アイコンの縁が何人集まっているかのインジケーターになる。参加者のアイコンをタップすると、誰が参加しているかの詳細が見える（音声） | 詳細に表示する項目、参加していない人にも見せるか |
| F6 | イベントの編集・削除 | 作成者だけがイベントを編集・削除できる（UI設計図） | 編集できる項目 |
| F7 | イベント内のトーク | 参加したイベントの中だけのトーク。今まで参加したイベントと今参加しているイベントのトークを一覧で表示し、トーク画面へ進む（UI設計図）。掲示板でイベントのカードをタップすると、そのイベントのチャットがポップアップし、普通のチャット欄のように使える（音声） | 参加していない人がカードをタップしたときにチャットを見られるか、参加を取り消したあとのトークの扱い、メッセージの種類（文字だけか） |
| F8 | 友達（フォロー） | 友達の一覧を表示し、友達を削除できる。QRや招待リンクで友達を追加する（UI設計図） | 「フォロー」と「友達」の違い（片方向か相互か）、承認の有無 |
| F9 | プロフィール | 自身のプロフィール（アイコン・名前）（UI設計図） | 編集の可否、他の人から見える範囲 |

作らないもの:
- グループチャット
- 暇かどうかが分かる機能
- 「行けたら行く」機能

### 矛盾・要確認
- 募集の公開範囲: アイデアマップは「グループ内で募集をかける」、UI設計図は掲示板を「(全体)」と書き、グループ作成は「フォロー欄」の下にある。募集をグループに出すのか、友達全体に出すのか不明
- トーク: アイデアマップは「グループチャット自体は要らない」、UI設計図には「参加したイベント内限定のトーク」があり、音声でもカードからイベントのチャットを開く。イベント内のトークはグループチャットとは別物として作るのか要確認

## 6. 画面（UI設計図より）
アプリ起動後、次の5つに分かれる。「（下）」は図の記載どおり（画面下部のタブを指すと思われるが不明）。

1. 掲示板（ホーム）(全体)
   - 人数・場所・時間・表示時間などを表示
   - イベントを選択 → 参加 → 参加の取り消し
   - 作成者のみ、イベントの編集・削除
   - 詳細は 6.1、6.2（手書きUI図と音声）
2. 誘うボタン（下）
   - 場所・時間・人数・表示時間を設定 → 公開
3. 参加したイベント内限定のトーク（下）
   - 今まで参加したイベントと今参加しているイベントのトークを表示 → トーク画面へ
4. フォロー欄（下）
   - 友達の一覧を表示 → 友達の削除
   - グループ作成 → 友達を選択、グループ名・プロフィールを入力
   - QRや招待リンクで友達追加
5. プロフィール（下）
   - 自身のプロフィール → アイコン・名前

不明: 起動時のログイン・登録画面、掲示板以外の画面のレイアウト・デザイン、画面間の戻り方

### 6.1 掲示板のイベントカード（手書きUI図・音声）
初期状態では、イベントを表す四角いカードがいくつか並ぶ（イメージ: docs/design/ui-image/01_home.png）。

| 位置 | 表示するもの |
|---|---|
| カードの外枠 | 残り時間のインジケーター |
| カード内の大きな丸 | 主催者（誘っている人）のアイコン |
| 主催者アイコンの縁 | 丸いインジケーター。何人集まっているかを表す |
| 主催者アイコンの下 | 主催者の名前 |
| アイコンの横・中央 | 誘うときのタイトル（例: カラオケ）、その下に時間（例: 19:00〜） |
| タイトルの下 | 現在参加している他の人のアイコン |
| 右側 | 図に「3/4」「40分」とある（音声で説明なし。参加人数／定員と残り時間と思われるが不明） |

- 大きな丸の位置: 音声では「右側」、図では左側に描かれている。どちらか不明（イメージ画像は図に合わせて左）

### 6.2 カードの操作（音声）
| 操作 | 結果 | イメージ |
|---|---|---|
| カードをタップ | そのイベントのチャットがポップアップする。上半分の詳細な情報は消え、タイトルだけが上に小さく表示され、その左に参加者のアイコンが並ぶ。普通のチャット欄のように使える | 02_event_chat.png |
| チャットの入力欄をタップ | 端末のキーボードが下半分に出て、チャット欄はその上に表示される | 03_chat_keyboard.png |
| 主催者のアイコンを指で押さえて右にスワイプ | イベントに参加する | 01_home.png |
| 参加者のアイコンをタップ | 誰が参加しているかの詳細が見える | 04_participants.png |

- 音声では「四角い縁をタップ」と言っている。カード全体のタップか、外枠だけのタップか不明（イメージ画像はカード全体として作成）
- ポップアップの閉じ方、スワイプとタップを区別する方法、参加の取り消しの操作: 不明

## 11. 開発の進め方

### 11.1 プロダクト・UI
- 画面を作る前に、コンセプトを1文、代表的な場面を3つ、中心にする「もの」を2つまで決める（内容は不明・要決定）
- 機能の一覧をそのまま画面やタブにしない
- DESIGN.md で色・文字・余白と「やらないこと」を先に決め、全員のAIエージェントがそれに従う（デザインの中身は不明）
- F2 の入力項目は最小限にする（項目は不明・要決定）
- 5章の F1〜F9 以外は作らない。機能を足すときは、先に仕様書を更新する
- チーム外の人に使ってもらって確かめる（方法は不明）

### 11.2 リポジトリ・GitHub 運用
- リポジトリを公開にするか GitHub Pro にして main を保護し、CI が通らないとマージできないようにする（公開範囲は不明・要決定）
- ワークフロー・DB 変更・認証の変更だけ、他の1人が見る
- マージは squash に統一し、マージ後にブランチを自動で削除する
- Issue テンプレートで「何を・なぜ・完了条件」の3行を必須にする。着手したら「作業中」とコメントし、自分を担当者にする。ラベルは3つ
- 進捗は GitHub Projects のボードだけで管理し、手で書く進捗まとめは作らない
- README は提出物なので作品紹介とデモ URL だけにする。開発情報は CONTRIBUTING.md、ルールは AGENTS.md に書く
- AGENTS.md とファイル構成（機能ごとのファイル）は、メンバーが作業を始める前に用意する

### 11.3 デプロイ（Cloudflare）
- staging と本番で D1 を分け、main へのマージは staging に出す。本番には、確認後にオーナーが出す
- DB の変更は追加だけにし、古いアプリでも動くようにする。CI で DROP/RENAME と既存マイグレーションの変更を検出する
- 公開後に DB の接続とバージョンを確かめる（/api/health など）
- Cloudflare のトークンは権限を絞り、本番用の Environment secret に置く
- 審査前に本番を凍結する（時刻は不明・要決定）

### 11.4 実装・デモ
- 定員を設ける場合は、定員の確認と参加を1回の処理でまとめて行う（定員の機能を作るかどうかは不明）
- 定期的にデータを取得する場合は、画面が見えていないときは止め、失敗したら間隔を空ける（Cloudflare の無料枠は1日10万リクエスト）
- セッションに有効期限を付け、ログインと登録に試行回数の制限を入れる
- スマホ実機での通しデモと、予備のデモ動画を用意する
- 中間の締切を置く（スケジュールは不明・要決定）
